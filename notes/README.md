# 📝 Technical Notes

This directory contains general notes, concepts, explanations, and learning material related to the Software Engineering project.

These notes are used to capture useful technical knowledge that may support current or future development work.

---

## 📌 Purpose

The `notes` folder is for information that is useful, but not necessarily a formal decision or a step-by-step guide.

Use this folder for:

- software engineering concepts;
- WPF and XAML notes;
- MVVM explanations;
- testing concepts;
- Git/GitHub observations;
- AI-assisted development reflections;
- useful reminders discovered during the project.

Basically, this is the place for knowledge that would otherwise vanish into browser tabs, screenshots, or the human attention span. A terrifying storage medium.

## 🧱 Example Note Structure

Use this format when adding a new note:

```md
# Topic Name

## Summary

Short explanation of the concept.

## Why It Matters

How this concept is useful for the project.

## Example

Code, diagram, or practical example.

## Related Project Area

Where this concept appears in the Student Registration System.
```

## 🔎 Current Project-Relevant Concepts

Important concepts for this project include:

| Concept | Project Relevance |
|---|---|
| MVVM | Separates WPF UI from application logic |
| ICommand | Connects UI actions to ViewModel behavior |
| XAML Binding | Connects UI controls to ViewModel properties |
| XML Persistence | Stores local application data |
| Unit Testing | Verifies service and business logic |
| Pure Functions | Keeps logic predictable and testable |
| Command Pattern | Encapsulates reset filter actions |
| Spec-Driven UI | Uses a design contract to constrain AI-generated UI |

---

## ✅ Usage Rule

A note should explain a concept clearly enough that it can be reused later without needing to reconstruct the whole thought process from memory.

Memory is not version control. Humanity keeps learning this the expensive way.
